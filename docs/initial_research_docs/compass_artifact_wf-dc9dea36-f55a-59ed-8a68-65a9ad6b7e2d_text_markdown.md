# The Agentic Data-Source Harness: A Layered Ecosystem Map & Product Roadmap (August 2026)

*Note on verification: Web search and fetch tools were confirmed functional at the start of this research; every major claim below is grounded in live 2025–2026 sources retrieved during the task (official docs, GitHub, vendor newsrooms, arXiv, Linux Foundation, and reputable press). Items that could not be verified to a primary source are explicitly flagged in Caveats.*

## TL;DR
- **Build a thin composition layer, not a monolith.** The winning architecture for a tech-stack- and sector-agnostic data-source harness is: MCP (2026-07-28 spec, now governed by the Linux Foundation's Agentic AI Foundation) as the wire protocol; a portable semantic layer aligned to Open Semantic Interchange (OSI v0.1, Apache 2.0); hybrid source-level + chunk-level retrieval; and a gateway that enforces identity and policy. The primitives now exist as open standards and OSS — your differentiation is orchestration, automatic semantic discovery, and governed shared memory, not re-implementing connectors.
- **Semantic grounding is the single highest-leverage investment.** Controlled 2025–2026 benchmarks converge: adding a semantic layer lifts text-to-SQL accuracy by +17 to +23 points (Cube), from 20% to 92.5% on TPC-DS (AtScale), and to near-100% for covered queries (dbt) — while raw enterprise schemas collapse GPT-4o to 10.1% on Spider 2.0. The semantic layer, not model choice, is the ceiling on agent data quality.
- **Context bloat, tool sprawl, and MCP's trust model are the real risks.** Seven MCP servers consumed 67,300 tokens — 33.7% of a 200k context budget — before any conversation began (Claude Code issue #11364, Nov 10, 2025). Tool poisoning, rug-pulls, and shadowing (Invariant Labs, April 1, 2025) exploit MCP's unconditional trust in tool descriptions. Mitigate with code-execution-with-MCP / Tool Search (≈85% token reduction) and gateway-enforced least-privilege from day one.

## Key Findings

1. **MCP is the de-facto substrate with a mature quarterly-to-biannual spec cadence.** The current finalized revision is **2026-07-28** — the largest revision since launch: a stateless protocol core, Multi Round-Trip Requests, header-based routing, cacheable list results, authorization hardening, and a formal Extensions framework. The prior finalized revision was 2025-11-25; the 2025-06-18 revision added structured tool output, elicitation, and classified MCP servers as OAuth Resource Servers requiring RFC 8707 Resource Indicators. In **December 2025 Anthropic donated MCP to the Agentic AI Foundation (AAIF)** under the Linux Foundation, co-founded with Block and OpenAI; platinum members include AWS, Anthropic, Block, Bloomberg, Cloudflare, Google, Microsoft, and OpenAI. Across Tier-1 SDKs, TypeScript and Python each crossed 1 billion total downloads.

2. **Agent-to-agent protocols have consolidated into one stack.** Google donated **A2A** to the Linux Foundation on June 23, 2025 (founding members AWS, Cisco, Google, Microsoft, Salesforce, SAP, ServiceNow). IBM's **ACP** (BeeAI) merged into A2A in August 2025, with the ACP team winding down and Kate Blair joining the A2A Technical Steering Committee. Cisco's **AGNTCY** (identity/discovery/observability) was donated July 29, 2025 and made interoperable with A2A and MCP rather than competing. As of August 2026, **A2A joined AAIF alongside MCP**, giving the "MCP for tools, A2A for agent collaboration" stack a single steward; A2A reached v1.0 and surpassed 150 organizations.

3. **The semantic layer is standardizing fast.** **Open Semantic Interchange (OSI)** launched September 23, 2025, led by Snowflake with Salesforce, dbt Labs, RelationalAI, and BlackRock backing; launch partners included Alation, Atlan, Cube, Hex, Honeydew, Mistral AI, Omni, Select Star, Sigma, and ThoughtSpot. The **OSI v0.1 spec is live under Apache 2.0** (announced ~January 27, 2026), with a project site at open-semantic-interchange.org and a stated plan to move to neutral, foundation-led governance. Amazon, Google, DataHub, Denodo, and others joined later; a Financial Services Semantic Working Group has begun meeting.

4. **The data-tooling market is consolidating around "data infrastructure for AI agents."** **Fivetran + dbt Labs** announced an all-stock merger October 13, 2025 and **completed it June 1, 2026** (~$600M combined ARR, 100,000+ data teams; George Fraser CEO, Tristan Handy President). dbt's **Fusion engine** — from the January 2025 SDF Labs acquisition, rewritten in Rust and ~30× faster at parsing than dbt Core — shipped in **dbt Core v2.0 (alpha, Apache 2.0)** at close, alongside an open **Agents Schema** standard designating a single warehouse schema as a shared agent context layer. Notably, Fivetran separately donated the competing **SQLMesh** framework to the Linux Foundation, signaling a bet on openness.

5. **Semantic layers dramatically improve agent accuracy — with converging evidence.** AtScale's whitepaper ("Enabling Natural Language Prompting with AtScale's Semantic Layer and Generative AI," using Gemini Pro 1.5 on TPC-DS) reports that a control system with only table schemas + PK/FK **achieved 20% accuracy, while the semantic-layer system achieved 92.5%** — including 70% (vs 10%) on the hardest high-complexity questions. Cube's paired benchmark across three frontier models found **+17 to +23 points** from the semantic layer (statistically significant, McNemar p ≤ 0.0015), and that model choice within tier was statistically insignificant — the data model, not the model, is the upper bound. dbt Labs' 2026 benchmark (Ganz & Perigaud) shows **Claude Sonnet 4.6 moving 90.0%→98.2% and GPT-5.3-Codex 84.1%→100.0%** on a modeled semantic layer. The foundational Sequeda et al. (2023) study found GPT-4 improved from **16.7%→54.2%** on an enterprise insurance schema when given an ontology instead of raw SQL. Crucially, semantic-layer failures are explicit refusals ("cannot answer") while text-to-SQL failures are confident wrong numbers.

6. **Enterprise text-to-SQL without semantics is unreliable.** Per the Spider 2.0 project, **GPT-4o's success rate is only 10.1% on Spider 2.0 versus 86.6% on Spider 1.0**; databases often exceed 1,000 columns, and even o1-preview solves only 17.1–21.3%. A 2026 CIDR paper found BIRD and Spider 2.0-Snow annotation error rates of 52.8% and 66.1% respectively — the benchmarks themselves are noisy, reinforcing the case for governed semantics over leaderboard chasing.

7. **MCP's security model is its biggest structural weakness.** Invariant Labs' "MCP Security Notification: Tool Poisoning Attacks" (**disclosed April 1, 2025**) states MCP "places too much trust in tool descriptions without sufficient validation or user transparency"; its PoC exfiltrated `~/.ssh/id_rsa` via a poisoned "add" tool in Cursor. Related classes: rug-pulls (post-approval tool mutation) and tool shadowing (one server manipulating another's tools). The **MCPTox benchmark (arXiv:2508.14925)**, across 45 real servers and 20 models, measured attack success rates up to **72.8%**. MCP provides no cryptographic attestation of tool-description integrity and no runtime re-verification. OWASP codified this as MCP03:2025 (Tool Poisoning); Trail of Bits proposed trust-on-first-use description pinning ("line jumping"); Invariant released **mcp-scan** as a detector.

8. **Context bloat is now acknowledged by MCP's own creators.** Anthropic's November 2025 "Code execution with MCP" post and the subsequent **Tool Search Tool** report **an 85% reduction in token usage** while maintaining full-library access (Opus 4.5 tool-use accuracy improved 79.5%→88.1% with Tool Search enabled). Cloudflare's Code Mode and Docker's Dynamic MCP push the same "don't load tools you aren't using" pattern. This materially changes agent architecture: expose MCP servers as code APIs and let the agent write code to call them, filtering intermediate results before they hit the model.

## Details — The Layered Ecosystem Map

### Layer 1 — Protocol (agent ↔ tool/data wire format)
- **MCP (Anthropic → AAIF/Linux Foundation).** Open standard, current spec 2026-07-28. Transports: stdio and Streamable HTTP (the 2026-07-28 revision made remote servers ordinary stateless HTTP workloads routable by standard infrastructure). Auth: OAuth 2.1 / Resource Server model with RFC 8707 Resource Indicators. Primitives: tools, resources, prompts, elicitation, structured tool output, plus official extensions (MCP Apps for sandboxed inline UI via SEP-1865; Tasks for async long-running work). **Strengths:** ubiquity, vendor-neutral governance. **Gaps:** trust model, context bloat, tool sprawl. **Openness:** fully open, permissively licensed SDKs.
- **A2A (Linux Foundation/AAIF).** Agent-to-agent discovery via "agent cards," delegation across trust boundaries; v1.0; embedded in Google Cloud, Azure AI Foundry, and AWS Bedrock AgentCore. **ACP** merged in; **AGNTCY** provides complementary identity/discovery/observability (Directory, Identity, SLIM messaging, observability).
- **OpenAI Agents SDK / function calling** and **LangChain Agent Protocol** remain framework-level complements; most now interoperate with MCP + A2A. The official reading (Google, Salesforce, Microsoft): MCP for capabilities, A2A for collaboration — complementary, not competing.

### Layer 2 — Gateway & Access (federation, policy, discovery)
- **IBM ContextForge / mcp-context-forge** (Apache-2.0; `mcp-contextforge-gateway` on PyPI, v1.0.7): federates MCP + A2A + REST/gRPC into one governed endpoint, 40+ plugins, OpenTelemetry observability, virtual servers for tool subsetting; Expedia Group layered quality grading and org-wide discovery on top without forking. A strong open-source base for the gateway tier.
- **Stacklok ToolHive** (Apache-2.0 core + Enterprise): container-isolates each MCP server with Cedar-policy authz, OIDC, and audit.
- **Docker MCP Catalog/Toolkit**, **Microsoft MCP Gateway** (MIT, Kubernetes routing), **Lasso MCP Gateway**, **mcp-proxy**, **Envoy AI Gateway** (Apache-2.0, MCP aggregation), **agentgateway** (Apache-2.0, LF data plane for MCP/A2A with RBAC), **Kong AI Gateway** (commercial REST→MCP), and **JFrog MCP Registry** (GA, supply-chain governance) round out the tier.
- **MCP Registry / discovery:** the official registry plus enterprise registries (Kong, TrueFoundry, Kiro). A registry is the discovery catalog; a gateway is the runtime enforcement point — most enterprises need both. Google shipped **50+ managed MCP servers** (GA + preview) at Cloud Next '26; **Microsoft Copilot Studio MCP** went GA.
- **Commercial tool-connectivity platforms:** **Composio** (~27K stars; 1,000+/3,000+ toolkits; $25M Series A led by Lightspeed, July 2025, ~$29M total — but disclosed a **May 2026 security incident** with exfiltrated customer API keys and GitHub OAuth tokens); **Arcade.dev** (MCP runtime / "secure action layer," **$60M Series A June 2026, $72M total**); **Klavis AI** (open-source MCP, Strata context-window-aware tool exposure); **Nango**, **Paragon**, **Pipedream** (acquired by Workday, Nov 2025), **Merge.dev**, **Airbyte**, **Fivetran**. Category thesis: catalog size is commoditizing; auth, governance, and context-window-aware tool exposure are the new differentiation axes.

### Layer 3 — Semantic / Metadata (business meaning, glossary, ontology, catalog)
- **Standards:** OSI v0.1 (Apache 2.0) is the emerging portable spec; dbt's **Agents Schema** is a parallel warehouse-native approach.
- **Headless/independent semantic layers:** **dbt Semantic Layer / MetricFlow**, **Cube / Cube Cloud** (ships an MCP server so agents call governed metrics as tools; D3 agentic analytics; an OSI launch partner), **AtScale**, **Malloy**, **LookML**.
- **Platform-native semantic models:** **Snowflake** semantic views + Cortex Analyst; **Databricks Unity Catalog metric views** (YAML-defined governed dimensions/measures) + Genie; **Microsoft Fabric**. The market has split into "headless/independent" (portability, e.g. Cube, dbt) vs "platform-native/walled-garden" (performance, zero-copy) philosophies.
- **Ontology / knowledge-graph vendors:** **Palantir AIP Ontology** (objects/links/actions/functions as a governed surface, Palantir MCP), **Stardog Voicebox** (NL → concept matching via embedded vectors → SPARQL → federated SQL over knowledge graphs, exposed via Stardog Cloud MCP; returns "cannot find an answer" when data is absent), **Timbr**, **data.world**, **Ontotext GraphDB**, **RelationalAI**.
- **Catalogs for AI:** **Atlan**, **Collibra**, **DataHub**, **Select Star** — increasingly positioned as context/governance suppliers to agents.

### Layer 4 — Retrieval / Query (hybrid source-level + chunk-level)
- **Agentic RAG:** the canonical survey is **Singh, Ehtesham, Kumar, Talaei Khoei & Vasilakos, "Agentic Retrieval-Augmented Generation: A Survey on Agentic RAG," arXiv:2501.09136** (Jan 15, 2025; companion repo ~1,559 stars). Design patterns: reflection, planning, tool use, multi-agent collaboration.
- **GraphRAG (Microsoft):** paper "From Local to Global" (arXiv:2404.16130); repo ~35.6K stars but **now in maintenance mode** (bug fixes/CVEs only) as frontier-model capabilities advanced; **LazyGraphRAG** (no up-front summarization) is the newer direction, available via Microsoft Discovery.
- **Text-to-SQL OSS:** **WrenAI** (~16.6K stars, semantic-layer-first via its MDL modeling language, Apache-2.0 core + AGPL components, 22+ sources — the most widely adopted by a clear margin); **Vanna** (RAG-first, ~20–23K stars, added user-aware RLS/audit, but the OSS repo was **archived March 2026** with a paid Vanna Cloud + v2.0 pivot); **DB-GPT** (fine-tuning); **Dataherald**. Consensus takeaway from teardowns: context/semantic strategy matters more than LLM choice, and no OSS project yet combines semantic layer + RAG + fine-tuning + self-learning well — an open niche.
- **Federated query engines:** Trino/Presto, DuckDB, Apache DataFusion, Ibis, Substrait, Apache Arrow ADBC, PostgreSQL FDW — the substrate for cross-source, source-level routing.
- **RAG frameworks:** LlamaIndex, LangChain/LangGraph, Haystack, RAGFlow, txtai, DSPy, Cognee. Retrieval best practice is hybrid dense + sparse (BM25) with a reranking stage.

### Layer 5 — Governance / Security
- **MCP threats:** tool poisoning, rug-pulls, shadowing, prompt injection via tool descriptions/results, and line jumping. Controls: **mcp-scan**, gateway-enforced least-privilege tool exposure, trust-on-first-use description pinning, OAuth 2.1 with Resource Indicators, and agent identity propagation (Snowflake shipped **Agent Identity GA** at Black Hat 2026; its Cortex AI Gateway adds MCP governance and data-exfiltration prevention).
- **Enterprise patterns:** row/column-level security propagated to agents (Vanna's user-aware model filters SQL per user permissions), agent identity brokering (AWS AgentCore Identity via Cognito/Entra/Okta), audit trails per agent action, and the registry-plus-gateway split (discovery + runtime enforcement).

### Layer 6 — Memory (governed shared state for MAS)
- **Mem0** (~48–61K stars, Apache-2.0, hybrid vector+graph+key-value, YC-backed) — best for personalization and self-hosting.
- **Zep / Graphiti** (Graphiti ~24–29K stars, temporal knowledge graph with fact validity windows; Zep Community Edition deprecated — self-hosting now means running Graphiti directly on Neo4j/FalkorDB/Kuzu). Benchmarks are disputed (LOCOMO 58.44% vs 75.14%; LongMemEval 63.8% vs Mem0 49.0% on GPT-4o).
- **Letta (MemGPT)** (self-editing tiered memory) and **Cognee** (ECL pipeline, hybrid graph+vector; lacks SOC 2/HIPAA) round out the tier. None yet models enterprise governance — definitions, lineage, access policy — inside memory. That is a clear, defensible gap.

## Recommendations — Staged Product Roadmap

**Architecture (compose, don't rebuild).** External wire protocol: MCP (2026-07-28, stateless Streamable HTTP, OAuth 2.1 + RFC 8707). Gateway tier: start from IBM ContextForge (Apache-2.0) for federation, discovery, policy, and audit. Semantic layer: align to OSI v0.1 and expose governed metrics to agents as tools (via Cube or dbt MetricFlow) rather than letting agents guess SQL. Retrieval: source-level federated routing (Trino/DuckDB/DataFusion) + chunk-level hybrid dense+sparse with reranking. Memory: Mem0 or Graphiti. Multi-agent collaboration: A2A.

**Phase 0 — MVP (0–3 months):**
- Ship an MCP server (stateless Streamable HTTP, OAuth 2.1 + Resource Indicators) fronting 2–3 heterogeneous sources (one warehouse, one SaaS, one document store).
- Adopt code-execution-with-MCP / Tool Search from day one to avoid the 67,300-token bloat problem.
- Wire in mcp-scan and least-privilege tool exposure through the gateway.
- **Threshold to advance:** >85% answer accuracy on a 100-question internal suite over the modeled sources; <5K tokens of tool-definition overhead per session.

**Phase 1 — v1 (3–9 months):**
- Add a semantic layer aligned to OSI; expose governed metrics as MCP tools. Target the +17–23-point / near-100%-on-covered-queries regime the benchmarks demonstrate.
- Add semantic-aware source-level routing (route each sub-query to the right engine/source) plus hybrid chunk retrieval with reranking.
- Add agent identity propagation and row/column-level security enforcement with per-agent audit.
- **Threshold:** >90% on covered queries; explicit "cannot answer" refusals rather than confident wrong numbers; full audit trail per action.

**Phase 2 — Platform (9–24 months):**
- Automatic lexicon/ontology discovery across heterogeneous sources; cross-source entity resolution; governed shared memory for multi-agent systems; A2A federation.
- Contribute converters/adapters to OSI to ride the standard rather than fight it.
- **Threshold to keep investing:** semantic drift caught automatically (definition changes flagged before they reach agents); measurable reduction in duplicate metric definitions across teams.

**Build-vs-integrate decisions:**
- **Integrate (don't build):** MCP SDKs; the gateway (ContextForge/ToolHive); connectors (Composio/Airbyte/Fivetran); memory (Mem0/Graphiti); federated engines (Trino/DuckDB); text-to-SQL base (WrenAI, semantic-first).
- **Build (your moat):** automatic semantic/ontology discovery, cross-source entity resolution, semantic-aware source-level routing, governed shared-memory semantics, and drift detection.

**Standards to align with:** MCP 2026-07-28; A2A v1.0; OSI v0.1 (Apache 2.0); OAuth 2.1 + RFC 8707; OpenTelemetry for observability.

**Differentiation opportunities (whitespace confirmed by research):**
- *Automatic lexicon/ontology discovery across heterogeneous sources* — OSI standardizes the exchange format but not discovery; no OSS project auto-generates portable semantics across mixed sources.
- *Cross-source entity resolution* — federated engines route queries but don't resolve the same entity across sources.
- *Semantic-aware source-level routing* — combine a Trino/DuckDB substrate with semantic-layer metadata to route to the right source before chunk retrieval.
- *Governed shared memory for MAS* — current memory tools (Mem0/Zep/Cognee) omit enterprise governance (definitions, lineage, access policy); embedding governance into shared memory is defensible.

## Caveats
- **Vendor benchmarks are self-reported.** Snowflake's >90% and Databricks' 84.5%/93% figures are internal (150-question and ~15–28-question suites), not independently verified. AtScale, Cube, and dbt benchmarks are vendor-run, though Cube's is a statistically rigorous paired design and the AtScale/dbt/Sequeda results corroborate each other. Treat the *magnitude* (semantic layers help a lot) as robust and *exact percentages* as directional.
- **Benchmarks themselves are noisy.** The 2026 CIDR analysis found 52.8% (BIRD) and 66.1% (Spider 2.0-Snow) annotation error rates; leaderboard positions should not drive architecture.
- **Fast-moving governance.** MCP's donation to AAIF (Dec 2025) and A2A joining AAIF (Aug 2026) are recent; membership tiers and steering committees are still settling. AAIF itself formed only in December 2025.
- **Metric snapshots vary.** MindsDB star counts (~37–39K) and Glean ARR (~$200–300M) differ by source; the $7.2B Glean valuation (June 2025 Series F) is the last confirmed mark. GitHub star figures throughout are point-in-time.
- **Composio's May 2026 security incident** is a live cautionary data point on centralizing OAuth tokens in a connectivity platform — weigh it if compliance is a priority.
- **Could not verify to a primary GA date:** precise GA dates for Denodo's and Dremio's AI-agent features (2026 positioning language rather than dated announcements); and exact OpenAI/Google MCP *client* adoption specifics beyond managed-server counts. These should be confirmed against vendor release notes before relying on them.
